# MobiLoop MCP v0.1.0-alpha.14

Pre-release published on 2026-09-23.

## Highlights

- Redaction now parses structured MCP JSON responses before redacting nested values. XML, source, and log strings remain protected without corrupting the client-visible JSON payload.
- Accessibility-label verification now evaluates only interactive and input-like UI nodes. Generic Android containers that are merely enabled no longer produce false positives.
- Added regression coverage for both behaviors.

## Live Device Verification

- Connected to a Genymotion Galaxy S24 running Android 15 with the installed MiniTakip Android application (`com.minitakip.app`, version `2.0.5`).
- Completed a non-mutating MCP stdio run: tool discovery, Appium UiAutomator2 session, stable screen and XML capture, accessibility analysis, session health check, log review, evidence collection, and clean session deletion.
- The run did not enter form data, create records, clear application data, or keep a device session open. Evidence remained local, run-scoped, and redacted.
- MobiLoop reported one real unlabeled Android button. No application crash was detected. Firebase Auth test-data state and device service warnings were classified separately from app failures.

## Verification

- Formatting, lint, TypeScript typecheck, static-site validation, package dry run, high-severity dependency audit, Docker build, and all 59 tests passed.
- The published GHCR image is smoke-tested through a read-only container and an MCP `initialize` request after publication.
