# MobiLoop 0.1.0-alpha.15

This alpha adds the standalone MIT-licensed mobile QA skill and project-local setup/diagnostics. The AI agent supplies reasoning and scoped patches; MobiLoop executes guarded tools and returns evidence.

## Installation

From the built source checkout:

```bash
node dist/src/cli.js setup --workspace /absolute/path/to/mobile-app --client codex --yes
node dist/src/cli.js doctor --workspace /absolute/path/to/mobile-app --target android
```

Clients include Codex, Claude Code, Cursor, and VS Code/Copilot. Preview with `--dry-run`; existing servers are preserved and changed files are backed up. Setup does not install SDKs or silently reset apps. See [installation](../INSTALLATION.md).

## Fixes And Verification

- Android/iOS loops reject failed assertions, use fresh retry sessions, and preserve structured setup/HTTP failures.
- Shared Flutter text entry handles Android hint-only inputs, focus changes, and iOS secure-field replacement with bounded stale recovery.
- Explicit, approval-gated `appium.hide_keyboard` / `hideKeyboard` verifies keyboard dismissal without blind navigation or repeated taps; stable-source observation can settle layout transitions before the next action.
- Log classification distinguishes caught diagnostics from fatal events and does not lose later crashes behind earlier warnings.
- Static security scans no longer flag standard XML metadata as application HTTP traffic; actual HTTP values remain detectable.
- Windows command shims use tested escaping; cross-platform CI includes clean package installation and generated-config MCP startup.
- Container publication scans a local candidate first and pushes that same image only after the blocking scan passes; registry/asset publication remains downstream.
- Login templates retain data and include authorization plus actual input/action steps. The optional hosted Android E2E passed all three native UI scenarios, keyboard verification, and its negative control on disposable Ubuntu API 35 and accelerated Windows AOSP API 30 emulators. Physical devices were excluded; exact revisions and evidence are in the onboarding follow-up.

Local Kotlin/Flutter Android and Flutter iOS validation is recorded [here](../validation/mobile-qa-android-ios-2026-10-15.md). The [onboarding follow-up](../validation/onboarding-alpha15-2026-10-15.md) records setup/React Native evidence and CI boundaries; a workflow definition alone is not a passing platform test.

## Boundaries

SDKs, Appium drivers, and emulators remain host prerequisites. Source scans are deterministic heuristics, not a penetration test. Skill adherence depends on the model/client. Physical-device testing is excluded. NPM registry publication is not enabled; do not assume an npm `latest` command installs this release. Publication requires the protected-main review, CI, image scan, and MCP Registry pipeline to succeed.
