## Deterministic Validation

The suite covers both successful and failing orchestration, retry/session isolation, cleanup, unavailable screenshots, and missing visibility prerequisites. The real stdio integration uses a disposable Git repository to execute discovery, a baseline scan and blocked gate, denied unapproved patch, approved guarded patch, scan comparison, fresh scan and passing gate, and report generation. It also checks missing Android tools and workspace/endpoint restrictions.

The skill's frontmatter passed the skill-creator validator. Referenced tool names match the actual registry. Formatting, lint, static-site validation, npm package dry run, and Docker build are checked separately. The Docker build runs the same test suite and includes the skill in the runtime image.

Final results: 70 of 70 automated tests passed locally and in the Docker build. Type checking, lint, formatting, static-site validation, and package dry run passed. The final read-only Docker runtime completed a real MCP stdio handshake, exposed 82 tools, and returned the effective patch approval policy. The standalone skill ZIP contains only `SKILL.md`, `LICENSE`, and `agents/openai.yaml`.

These checks validate tool behavior and packaging. They are not an independent model evaluation of skill adherence, and do not establish runtime compatibility with every supported-format client.

The native Android fixture session was created, but its first page-source observation returned HTTP 500: UiAutomator2 timed out waiting for the active window's root `AccessibilityNodeInfo`. Both attempted Appium sessions were deleted. No scenario reached text entry or its outcome assertions. The native invalid-email scenario is blocked; the remaining native and Flutter scenarios were not executed. The installed binaries were not rebuilt, installed, or cleared. MiniTakip data was not edited.

Local attempt summaries are under `.mobiloop/runs/mobile-qa-device-2026-10-15T15-01-44-514Z` and `.mobiloop/runs/mobile-qa-device-2026-10-15T15-06-07-737Z`. ## Reproduce

Run `npm test` for deterministic coverage. For live tests, restore a responsive test device, start Appium, make `adb` available on `PATH`, and run `npm run test:device` with `MOBILOOP_TEST_DEVICE` and `APPIUM_SERVER_URL` set. The runner only launches the two named MobiLoop demos and stores a local summary and evidence.
